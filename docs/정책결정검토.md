# 정책 결정 및 구현 기준

## 종료된 사업의 기존 대기 지출

- 종료 사업에는 신규 지출을 등록할 수 없다.
- 종료 전에 접수한 `PENDING` 지출은 승인·반려·취소할 수 있다. 승인은 확정 예산 상태와 현재 지출 한도를 계속 확인한다.
- `PBL_WORKFLOW.PROCESS_EXPENSE`는 사업 상태로 기존 지출 승인을 차단하지 않는다. 검증 스크립트에는 사업을 종료한 뒤 기존 대기 건을 승인하는 사례를 포함한다.

## 기능권한 기준

- 업무 권한의 기준은 `PERMISSION`과 `ROLE_PERMISSION`이다. 각 업무 패키지는 활성 사용자와 활성 역할, 기능 코드 매핑을 확인한다.
- 학생 본인 요청·조회는 기능권한 확인과 소유권 확인을 모두 통과해야 한다.
- `sql/fixtures/01_common_seed.sql`은 독립 검증용 기능 코드와 학생·일반관리자 권한 매핑을 담고, 마스터 역할에는 전체 기능 권한을 연결한다.
- 기능권한 코드가 없거나 역할 매핑이 없으면 업무를 거부한다.
- 운영 환경에서 동일 스키마에 직접 테이블 DML 권한을 주면 패키지 검사를 우회할 수 있으므로, 애플리케이션 계정에는 패키지 실행 권한만 부여한다.

## 만족도 조사 문항과 응답

- 문항 추가·수정·비활성화는 `DRAFT` 조사에서만 허용한다. `OPEN` 이후 문항은 결과와 기존 응답의 의미를 보존하도록 유지한다.
- 응답을 시작한 학생도 조사 상태가 `CLOSED`이거나 조사 기간을 벗어나면 답변 수정 및 제출을 할 수 없다.
- 답변은 점수 1~5 또는 공백이 아닌 주관식 내용 중 하나를 반드시 가져야 한다. DB CHECK 제약과 패키지 검증을 함께 적용한다.
- 답변 수정 시 이전 값·새 값·처리자·시각을 답변 변경이력 테이블과 공통 `CHANGE_LOG`에 저장한다.
- 만족도 시드는 현재 월의 첫날부터 마지막 날까지를 조사 기간으로 사용하며, 조사 2개와 응답 레코드 10건을 생성한다.

## 검증

- `sql/04_tests.sql`과 `sql/07_satisfaction_tests.sql`에 종료 사업 지출 승인, 빈 답변 차단, 조사 종료 후 수정·제출 차단, 답변 이력·공통 로그 검증 사례를 둔다.
- 이 변경을 반영한 통합 Oracle 실행 검증은 별도로 수행해야 한다.
