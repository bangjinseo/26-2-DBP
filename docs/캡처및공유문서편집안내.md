# 지선 담당 보고서 캡처·편집 안내

공유 문서에는 `공유문서_지선담당_보고서.md`의 본문1~12장을 옮기고, 부록A(컬럼 정의)와 부록B(SQL)는 팀 문서 형식에 맞춰 뒤에 배치한다.
문서 전체가 지선 담당 범위이며 공통 테이블 최종안을 별도로 작성할 필요는 없다.
팀 정책이 바뀌면 정책·SQL·검증 예상값을 함께 수정한다.

## 캡처 배치

| 보고서 위치 | 캡처할 내용 | 포함할 증거 |
|---|---|---|
| 2장 | 빈 실습 스키마의 생성 전후 | 테이블0개 → DDL/시드 성공 → 테이블17개, 주요 데이터 건수 |
| 8장 Q05~Q07 | 마일리지 조회 | 학생1~4의400/130/80/200점과 나머지0점, 프로그램400/50/360점, 대기2건 |
| 8장 Q08~Q09 | 예산 조회 | 7개 항목, 무지출·0원 항목, 교수/주체별 승인 합계 |
| 9장 | 자동 검사 결과 | 주요 오류·한도·롤백 PASS와 ALL TESTS PASSED |
| 10장 | 승인 전후 | 학생5 0→100→0, 연구활동비10만→15만→10만 |

0개부터 생성하는 장면이 필요할 때 기존 PBL2를 삭제하지 않는다. 새 빈 전용 계정에서 run_demo.sql을 실행한다.
현재 보고서의 생성 성공 사실은 저장된 SQL 실행 원문을 근거로 한다. 아직 없는 캡처를 첨부한 것으로 표시하지 않는다.

## 금액이 잘리지 않게 확인하는 조회

SQL Developer에서 아래 SELECT만 선택하고 Ctrl+Enter로 실행하면 표 형태 결과를 캡처하기 쉽다.
승인 전후 시연은 F5로 실행하며, 아래 조회는 원하는 단계 사이에 같은 연결에서 수행한다.

```sql
SELECT student_id, student_name, total_mileage
FROM v_student_mileage WHERE student_id=5;

SELECT item_name, current_amount, spending_limit,
       approved_expense, balance, available_limit, execution_rate
FROM v_budget_summary WHERE project_budget_id=4;
```

스크립트 출력 캡처에서는 오른쪽 금액이 잘리지 않도록 결과 영역을 넓히거나 위처럼 필요한 컬럼만 조회한다.
직접 실행한 결과의 숫자나 오류 메시지를 편집해 바꾸지 않는다.
