## 아현에게 전달할 수정 요청

main 통합본의 만족도 파트에서 다음 항목을 확인했다. ahhyeon 브랜치에서 수정하고 ahhyeon → main PR로 검토를 요청한다.

1. 조사 시연 날짜 고정: sql/03_satisfaction_seed.sql은 2026-10-01~2026-10-31로 고정돼 있어 기간 밖에서 run_demo가 실패한다. 실행일 기준 시드 등으로 재현 가능하게 하고 업무 마감 검증은 유지한다.
2. 마감 후 응답 처리: sql/03_satisfaction_schema.sql의 start_response만 조사 기간과 OPEN 상태를 검사한다. answer_question·complete_response에도 마감 검사를 적용한다. 종료 전 시작한 응답도 CLOSED 전환 또는 기간 만료 후에는 수정·제출되지 않는지 검사한다.
3. 빈 답변 제약: ck_survey_detail_value에 명시적인 NULL·공백 거부를 추가한다. (score=NULL, answer_text=NULL) 및 공백 문자열 입력을 직접 INSERT해 거부되는지 확인한다. 정상 점수·주관식은 허용해야 한다.
4. 권장 데이터 규모 보완: 현재 시드는 조사 1개·응답 헤더 4개다. 과제의 권장 최소 규모는 조사 2개 이상, 조사별 문항 3개 이상, 응답 헤더 총 10개 이상이다. 이는 필수 실행 오류와 구분하되 제출 전 보완을 권장한다. 시드 변경 시 예상 집계값과 테스트도 함께 수정한다.

회귀 기준: 기존 업무 테스트를 유지하면서 날짜·마감·빈 답변의 새 검사가 통과하고, 실패 후 응답·로그 상태가 변하지 않아야 한다.

## 진서에게 전달할 보완 요청

PBL1 요구사항에 학적 정보의 코드값과 변경 이력 관리가 포함돼 있다. main에는 STUDENT_STATUS_HISTORY 테이블이 있지만 현재 학적 변경과 이력 입력을 함께 수행하는 SQL·패키지 경로 및 검증은 없다.

jinseo 브랜치에서 다음을 보완하고 jinseo → main PR로 검토를 요청한다.

1. 관리자가 학생의 현재 학적상태를 변경하고 이전·신규 상태, 변경자, 변경일시, 사유를 이력에 남기는 처리 추가.
2. 현재 학생 상태·학적 이력·공통 변경로그를 하나의 트랜잭션으로 처리하고 중간 실패 시 롤백.
3. 정상 변경, 학생 권한 거부, 없는 상태코드 거부, 동일 상태 처리 정책, 실패 시 데이터·이력·로그 복원 검증.
4. 구현 정책과 실행 순서를 문서에 추가.

별도 저장 프로시저 형식 자체가 필수인 것은 아니다. SQL 시나리오로 구현해도 되며, 일반 연락처 수정 요청 승인과 학적 변경은 구분한다.
